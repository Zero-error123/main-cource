# 검증 기록

검증일: 2026-09-23. 로컬 HTTP 서버와 Playwright가 제어하는 Chrome에서 확인했습니다. 이 문서는 로컬 결과이며 배포된 사이트를 검증했다는 의미가 아닙니다.

## 실제 API와 화면

| 검사 | 결과 |
| --- | --- |
| 실제 GitHub API | 직접 만든 공개 저장소 3개 표시, Fork 제외 |
| 언어 필터 | Python 1개로 필터 후 전체 복구 |
| 캐시 | 반복 새로고침에서 최초 1회만 실제 API 호출 |
| 테마 | 다크 모드 전환 후 새로고침해도 유지 |
| 반응형 | 320 / 390 / 768 / 1024 / 1440px에서 가로 넘침 없음 |
| 모바일 메뉴 | 기본 숨김, 토글, Escape 닫기, 섹션 이동 후 닫기 |
| 포커스 | 앵커 이동 후 해당 섹션, 폼 오류 시 첫 오류 필드 |
| 스크롤 | 70px에서 헤더 변화·탑 버튼 숨김, 350px에서 탑 버튼 표시 |
| 맨 위로 | 탑 버튼 클릭 후 scrollY 0 |
| 이미지 | 로컬 프로필 이미지 로딩 정상 |
| JavaScript | 페이지 실행 오류 없음, 두 JS 파일 구문 검사 통과 |

## 폼

- 빈 제출 시 이름·이메일·메시지 3개 오류를 각각 표시합니다.
- 이름에 공백만 입력하면 거절합니다.
- `invalid@email`은 거절하고 `hello@example.com`은 허용합니다.
- 정상 입력 후 성공 안내와 실제 전송이 없다는 설명을 표시합니다.
- 성공 후 입력을 바꾸면 성공 상태가 해제됩니다.
- 입력·검증 중 POST 요청이 발생하지 않음을 확인했습니다.

## 실패 상태와 접근성 보조 동작

다음 API 실패는 **브라우저 요청 가로채기로 만든 모의 응답**입니다. 실제 GitHub에 반복 오류 요청을 보내지 않았습니다.

| 모의 조건 | 확인 결과 |
| --- | --- |
| 지연된 응답 | 로딩 스피너·aria-busy 표시 후 정상 카드 전환 |
| HTTP 403, 429 | 요청 제한 안내와 재시도 버튼, 정상 응답으로 복구 |
| HTTP 404, 500 | 오류 UI와 재시도 버튼, 정상 응답으로 복구 |
| 빈 배열 | 표시할 프로젝트가 없다는 안내 |
| Fork·보관·비공개 항목만 존재 | 카드 제외 후 빈 상태 |
| 네트워크 연결 실패 | 네트워크 오류 안내 |
| 12초 무응답 | 가상 시계로 12초를 진행한 뒤 AbortController 취소·오류·재시도 표시 확인 |
| 배열이 아닌 JSON | 응답 형식 오류 안내 |
| 이름·설명에 HTML 문자열 | 텍스트로 표시, img/script 요소 생성이나 스크립트 실행 없음 |
| localStorage·sessionStorage 차단 | 오류 없이 프로젝트 조회와 테마 전환 동작 |
| 시스템 다크 모드 | 최초 다크 적용, 저장한 선택이 없으면 시스템 변경도 반영 |
| Intersection Observer | 스크롤 시 대기 클래스 제거 후 등장 |
| 모션 감소 설정 | 숨김·이동 애니메이션 없이 콘텐츠 표시 |

## 반복 동작과 메모리

20회 준비 동작 후 기준값을 측정하고, 테마·메뉴·필터·폼 입력·섹션 이동을 각각 포함한 루프를 **500회** 수행했습니다. 전후 같은 브라우저 탭에서 GC 후 DevTools의 DOM 카운터를 확인했습니다. 데이터는 모의 저장소 2개로 고정했습니다.

| 항목 | 전 | 후 |
| --- | ---: | ---: |
| JavaScript 이벤트 리스너 | 53 | 53 |
| DOM 노드 | 662 | 655 |
| 사용 중 JavaScript heap | 2,244,060 bytes | 2,286,140 bytes |

이 검사에서 리스너·DOM 노드가 누적되는 현상은 없었습니다. 모든 등장 요소를 확인한 뒤 관찰 대기 요소는 0개였습니다. Heap의 소폭 차이는 이 단일 측정만으로 누수라고 판단할 수 없으며, 이 결과가 모든 환경에서 누수 부재를 보증하지는 않습니다.

코드에서는 요청 타이머를 `finally`로 해제하고, 완료된 관찰자를 정리합니다. 동적 카드마다 이벤트를 붙이지 않고 상위 요소에 위임합니다. 검증용 브라우저 컨텍스트는 각 검사 종료 시 닫았습니다.

## 수동 재현 방법

1. Live Server로 사이트를 열고 화면 폭을 390px, 768px, 1440px로 변경합니다.
2. 메뉴와 테마를 누른 뒤 새로고침해 테마 유지를 확인합니다.
3. Projects에서 언어 필터를 바꾸고 카드의 GitHub 링크를 확인합니다.
4. 폼을 빈 상태·잘못된 이메일·정상 입력 순서로 제출합니다.
5. 오류 상태를 재현할 때는 개발자 도구에서 사이트의 **sessionStorage** 캐시를 지운 뒤 Network를 Offline으로 바꾸고 새로고침합니다. Online으로 복구한 뒤 재시도합니다.
6. 요청을 반복해 실제 API 한도를 소모하지 않도록 주의합니다. HTTP 상태별 확인은 요청 모의 도구를 사용합니다.

## 배포 검증

GitHub 소스 업로드를 완료했고 [첫 자동 실행](https://github.com/Zero-error123/main-cource/actions/runs/35809881027)에서 저장소 체크아웃과 JavaScript 문법 검사가 통과했습니다. Pages가 비활성화되어 Configure Pages 단계가 실패했습니다. 소유자가 Pages의 Source를 GitHub Actions로 설정한 뒤 배포를 재실행하고 실제 URL에서의 결과를 추가해야 합니다.
